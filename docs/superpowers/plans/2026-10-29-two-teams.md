# Two Teams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the one-team mode with two teams rating each other: captain links, both-side roster, all-must-answer reveal, Min/Avg/Max received next to Expected.

**Architecture:** Same layering as before: `src/match.js` (pure), `src/matchstore.js` (D1), `src/matchapi.js` (HTTP, mounted at `/api/matches`), pages `/match` and `/m/*`. The one-team files (`team.js`, `teamstore.js`, `teamapi.js`, `team*.html/js`, their tests) are deleted in Task 1 and their tables dropped by migration 0006.

**Tech Stack:** Unchanged.

**Spec:** `docs/superpowers/specs/2026-10-29-two-teams-design.md`

## Global Constraints

- Sides of 3–12 (captain + 2–11 others, raised from 8 at the owner's request 2026-10-29); duplicate nicknames within a side (case-insensitive) → 400. Team names and nicknames via `validateName`.
- Scores body `{ given, predicted }`, both `{c,r,i,s}` integers 1–10, via the existing `validateScores`.
- Reveal only when `matches.revealed_at` is set; set when side B exists and every remaining member of both sides has scores.
- A GET never contains another member's numbers or token. `reveal` contains aggregates only.
- Removal/leave floor three per side, enforced in the DELETE statement; lost race → 409.
- Removed-name marker `nickname = ''`, `token IS NULL`. Expiry 90 days.
- S labels verbatim from the spec. No inline styles (CSP).
- Commit after each task with the attribution lines in use.

## Review Focus

1. The unclaimed B captain link must reject score/remove/delete with 409 and must not let a GET see any side-A links. (Task 3.)
2. A side-A member must not see the B captain link; only the A captain sees it, and only until B is set up. (Task 3.)
3. Side A members who answered before side B existed must count as answered after setup, and the reveal must still wait for every B member. (Task 3.)
4. The Expected column for a team must be that team's own predictions, never the other side's. (Task 1 `aggregate` test with asymmetric numbers.)
5. Setup of side B with a nickname that duplicates one on side A is allowed (different teams, different people); duplicates within side B are 400. (Task 1 `validateSetup` test.)
